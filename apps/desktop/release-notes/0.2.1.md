This release fixes how the app reads Steam sales and CSFloat listings on accounts with a long
history, and stops a listing that sold quickly from being sent again. The trading record is not
upgraded: 0.2.1 opens the record 0.2.0 left as it is.

**A listing that sells before the next look is not listed again.** When a Steam listing sold
before the app next read the market, the book never showed it, the app took the request as never
sent, and it sent it again. A request missing from the book now counts as not sent only while the
item is still in the inventory. Once the item is gone, the app waits for the sales history, ties
the sale to the order and shows it sold.

**Sales history on long accounts.** The market history used to be read from the newest event to the
oldest on every pass. On an account with tens of thousands of events Steam rate-limited the read
about twenty pages in, every time, so sales never reached the record. Each pass now reads what is new
and a few older pages, two minutes apart until the whole log is covered, and every page counts
against Steam's limit like any other request.

**Several CSFloat delists at once.** When more than one CSFloat delist was waiting, only the first
was read back: the others waited for good while the first was read every five seconds. Each listing
is now read on its own. A CSFloat refresh also no longer reads every past sale one at a time when its
trade already explains it.

**Rate limits.** Reads of one Steam or CSFloat endpoint now share that endpoint's budget, rather than
each item having its own, so reading a hundred listings one by one no longer outruns the venue. When
one part of an account backs off after an error, the window names it ("sales history is retrying
after …") and the rest of the account keeps reading.

**Work panel.** A retrieve from a storage unit no longer says it went "into" the unit it came out of.

**For developers.** `apps/host` runs the same engine without a window: a command line and an HTTP
surface over one trading record, with the venues supplied by a ports module you name.
`packages/runtime` holds the command schema and the dispatch table the desktop and the host share.
